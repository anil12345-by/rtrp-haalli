E. Network settings – Security Group
This is very important.

Create a new security group.

Configure inbound rules:
Type	Port	Source
SSH	22	My IP
HTTP	80	0.0.0.0/0
Custom TCP	8080	My IP initially

Why?
- Port 22: SSH connection from your computer.
- Port 80: HTTP traffic.
- Port 8080: Tomcat application access.
For this learning setup, restrict port 8080 to your own IP. If you need public access for demonstration, you can temporarily allow 0.0.0.0/0, but this exposes the Tomcat port to everyone.

Do not allow SSH from 0.0.0.0/0.

7. Connect to EC2 using CMD (SSH)
Now we'll connect your Windows laptop to the AWS Linux server.

Go to:
EC2 → Instances → Select LibraryWebApp-Server → Connect


You can use the browser-based EC2 Instance Connect option, or connect through CMD as follows.
Step 1. Locate your PEM file
Suppose your downloaded file is in Downloads:
C:\Users\LENOVO\Downloads\library-key.pem


Step 2. Open CMD
Execute:
cd C:\Users\LENOVO\Downloads


Step 3. Connect using SSH
Get your instance's Public IPv4 address from the EC2 dashboard.

Run:
ssh -i "library-key.pem" ec2-user@YOUR_PUBLIC_IP


For example, replace YOUR_PUBLIC_IP with the actual public IP shown by AWS.

The username ec2-user is used for Amazon Linux 2023.

If prompted:
Are you sure you want to continue connecting?


Type:
yes


You should now see a Linux terminal prompt similar to:
[ec2-user@ip-172-31-xx-xx ~]$


Connected to AWS EC2
You are now controlling a remote Linux machine from your Windows laptop!

AWS also supports browser-based connection through EC2 Instance Connect. 
Amazon Elastic Compute Cloud+2

Amazon Corretto 21+1

10. Install Apache Tomcat
We need Tomcat to run your Java web application.

First create a directory:
sudo mkdir -p /opt/tomcat


Change directory:
cd /opt/tomcat


Download a compatible Tomcat release from the official Apache Tomcat downloads page:
Apache Tomcat 10.1 downloadsFor your practical, use the latest Tomcat 10.1 binary tar.gz release if your application uses Jakarta Servlet APIs.

Download the binary archive to your Windows laptop or directly to EC2. If downloading directly, use the exact .tar.gz download link from Apache:
wget "PASTE_OFFICIAL_TOMCAT_TAR_GZ_URL_HERE" -O tomcat.tar.gz


Extract it:
sudo tar -xzf tomcat.tar.gz -C /opt/tomcat --strip-components=1


Give execution permission:
sudo chmod +x /opt/tomcat/bin/*.sh


Start Tomcat:
sudo /opt/tomcat/bin/startup.sh


Check the logs:
sudo tail -f /opt/tomcat/logs/catalina.out


Press Ctrl+C to exit log monitoring. This does not stop Tomcat.

Important: If your existing LibraryWebApp uses javax.servlet, use Tomcat 9 instead of Tomcat 10.1. The application and server versions must be compatible.

13. Transfer WAR file from Windows to AWS EC2
This is an important practical step.

We'll use the scp command to transfer the WAR file from your laptop to the EC2 server.

Open a new CMD window.

Execute:
cd C:\Users\LENOVO\eclipse-workspace\LibraryWebApp


Now execute:
scp -i "C:\Users\LENOVO\Downloads\library-key.pem" target\LibraryWebApp.war ec2-user@YOUR_PUBLIC_IP:/home/ec2-user/


Replace YOUR_PUBLIC_IP with your actual EC2 public IP.

What does this command mean?
Part	Meaning
scp	Secure Copy
-i	Specifies private key
target\LibraryWebApp.war	Local WAR file
ec2-user	Remote Linux username
YOUR_PUBLIC_IP	EC2 server address
/home/ec2-user/	Destination directory

After execution, your WAR file is transferred to AWS.

AWS supports SCP for transferring files to Linux EC2 instances. 
Amazon Elastic Compute Cloud+1

14. Deploy WAR file in Tomcat
Return to your existing SSH terminal.

Check whether the WAR file arrived:
ls


You should see:
LibraryWebApp.war


Copy it into Tomcat's webapps directory:
sudo cp LibraryWebApp.war /opt/tomcat/webapps/


Set permissions:
sudo chmod 644 /opt/tomcat/webapps/LibraryWebApp.war


Tomcat automatically detects and deploys WAR files placed in its webapps directory when automatic deployment is enabled.

Check the deployment logs:
sudo tail -f /opt/tomcat/logs/catalina.out


Look for a successful deployment message.

Press Ctrl+C to exit.
